# 新版功能操作说明

本指南说明课表学期、课程修改、批量提醒和 Todo 新功能的实际用法。完整安装、Tailscale 远程访问和升级方式见[本机测试与服务器部署操作指南](setup-guide.md)。

## 1. 学期与课表

### 学期自动选择和手动查看

课表根据所选日期自动匹配有效学期。课表页面的“查看学期”默认是“按日期自动选择”；选择一个具体学期后，页面跳到该学期第一周，便于查看旧课表。回到自动选择后会显示今天所在学期。

导入课表时填写学期名称、第 1 周周一和学期结束日期。旧版本已经导入的学期没有结束日期，数据库升级时会暂按“第 1 周周一之后第 125 天”推算，也就是第 18 周周日。页面会显示“推算”，请对照学校校历修改“学期结束日期”并保存。保存后系统不再把它当作推算值。

超过学期结束日期后，自动查询不会继续显示该学期课程；下一个学期的课表也不会提前覆盖尚未结束的学期。

### 修改整学期课程或只改某一天

周视图或日视图里的课程卡片仅显示名称、时段、教师和地点。点击课程卡片后，左侧详情面板会显示课程轮次和可用操作：

- **编辑学期课程**：修正名称、星期、节次/时间、周次、单双周、地点、老师和备注。更改作用于整个学期后续符合规则的上课日期。
- **调整本次**：只修改当前日期的节次、时间、地点、老师或备注，不影响其他日期。
- **删除整门课**：从整个学期移除这门课，并取消相关的未发送课前提醒。网页会再次确认。
- **本次停课/恢复**：在“调整本次”面板里可只取消当天这一次。取消后日期标题下会显示停课课程和“恢复”按钮。

修改节次时同时填写开始与结束节次。使用自定义时钟时间时同时填写开始和结束时间。周次可以写成 `1-8,10-16`；留空时按单双周规则贯穿整个学期。

## 2. 批量设置课程提醒

可以直接在微信里说：

> 把这学期所有第三节开始和第八节开始的课，都设置成提前 25 分钟提醒。

Agent 会先按**课程开始节次**筛选，而不是按课程是否包含该节筛选。它会列出学期、课程编号、名称、星期和节次，并明确显示“尚未修改”。核对列表后，在下一条消息单独回复：

> 确认

随后 Agent 才应用本次预览。预览 15 分钟后过期；若期间课程资料发生变化，系统会拒绝旧预览并要求重新查看。没有匹配课程时不会做任何修改。要关闭批量提醒时，可以说关闭指定节次课程的提醒，预览确认流程相同。

在详情面板中可以新增或调整课前提醒，并修改整学期课程轮次；微信也支持按课程名称或已查询的课程编号修改周次、单双周和提醒。

## 3. 待办与日历

### 日、周、月视图

待办页面提供“清单 / 日 / 周 / 月”视图。用左右箭头切换日期范围，用日期框跳到具体日期；月视图点击某天日期可进入该日视图。设置了开始与结束日期的待办会覆盖两端之间的每一天；跨越当前周或月边界的任务也会显示在可见区间内。日历卡片只显示任务摘要，点击卡片后左侧详情面板才显示时间范围、提醒和修改/完成/删除操作。没有开始或结束日期的任务会列在日历下方的“未设置日期”区域。搜索、状态和日期筛选会同时作用于清单与日历。

### 开始时间、结束时间和提醒

单次待办可以设置开始和结束日期/时刻，也可以只设置一端或不设置时间。提醒可以添加多个完整日期和时刻。分类、备注、优先级和重要/紧急四象限可以一起设置。

### 每日、每周、每月重复

重复待办支持每日、每周指定星期和每月指定日期。填写重复开始日期和停止日期，并可为每一期设置开始/结束时刻和多个提醒时刻。新建或修改重复规则都要求停止日期，避免意外无限生成。每月重复还要选一个日期，例如每月 31 日；某个月没有 31 日时会按当月最后一天执行。编辑重复任务时选择“本期”或“整个系列”。

已有旧版的无限重复 Todo 或每周个人安排会继续运行，页面会显示提醒标识。编辑它的重复规则时设置停止日期即可收束未来计划；只改任务标题等普通内容不强迫改写旧重复规则。

## 4. 分类和重要/紧急四象限

任务分类提供学习、锻炼、生活、项目、工作和其他，网页用不同颜色显示。

重要性和紧急性分别记录，网页显示四种组合：

| 组合 | 页面建议 |
| --- | --- |
| 重要且紧急 | 优先处理 |
| 重要、不紧急 | 计划安排 |
| 不重要、紧急 | 快速处理 |
| 不重要、不紧急 | 稍后再看 |

旧版优先级 3–5 会迁移为“重要”，1–2 会迁移为“不重要”。网页默认保留“自动判断紧急度”：未完成任务到期日是今天或未来两天内时标记为紧急。也可在四象限选项中明确指定紧急或不紧急，微信自然语言工具同样支持手动覆盖。

## 5. 微信自然语言操作例子

- “明天下午两点到四点写报告，提前一天和开始前半小时提醒我。”
- “每周一和周三背单词，做到 12 月 20 日结束。”若没有说明开始日期，Agent 会先询问。
- “将这个系列的提醒统一改成每天早上 8 点和晚上 8 点。”Agent 应找到目标系列，再修改整组设置。
- “改一下今天这门课的教室到三教 402。”Agent 应使用单次课程调整，不修改整学期规则。
- “删除这门课。”整门课程删除前 Agent 会先显示课程名称，并要求再次确认。

Agent 应区分查课表、问课程详情、修改课程、批量提醒和 Todo 操作；用户问课程问题时先识别具体意图，不应一律只返回整张课表。回答可以自然、简短，适量使用表情符号，不要让每次回复像同一段模板。

## 6. 服务器版本更新

每次更新先备份并检查工作树，再拉取代码。到服务器项目目录后按此顺序执行：

```bash
git status --short
git rev-parse HEAD
./scripts/backup.sh
git pull --ff-only origin main
./scripts/up.sh
sudo docker compose restart astrbot
sudo docker compose ps
curl -fsS http://127.0.0.1:8080/healthz
sudo docker compose logs --tail=100 assistant-api astrbot
```

记录 `git rev-parse HEAD` 显示的旧提交号，以备排查。`git status --short` 有输出时，先检查并保存本机修改，再更新。数据库结构迁移会在应用启动时执行；迁移前的 SQLite 自动快照与手动备份都在 `backups/`。`restart astrbot` 用于让进程重新加载挂载的微信插件代码。看到 API 健康检查返回 `{"status":"ok"}`，并在 Todo 网页和微信工具中分别试一项只读查询后，再继续日常使用。

如升级异常，先保留日志和备份，不要清理 Docker 数据或删除 `data/`。数据库结构升级通常不支持把旧版程序直接接到新版数据库上；按[运维回滚说明](operations.md#更新与回滚)恢复代码和对应数据库快照。
